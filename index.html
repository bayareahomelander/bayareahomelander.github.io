Featured project

Onyx

Grammar-constrained LLM inference engine

Onyx makes an 8B model generate up to 2.4× faster while producing exactly the same output, token for token. A small draft model guesses ahead; the large target model checks every guess in one pass and keeps only what it agrees with. A Rust grammar engine forces every token to fit a regex or JSON Schema, so structured output is valid by construction.

  • 1.49×faster overall across a 48-request benchmark, output identical
  • 2.44×faster on code; 2.1× on JSON Schema and regex output
  • 0.3 msadded time to first token, down from 637 ms
  • 1.45×on Apple Silicon (MLX, 4-bit), in a separate implementation

How it got there

  • The draft runs as hand-written CUDA graphs. Reimplementing the draft's decoder step over a static KV cache cut it from 7.5–9.8 to 4.1–4.4 ms per token, and raised the overall speedup from 1.17× to 1.49× in one week.
  • Output stays bitwise-identical. Scoring several positions at once can round differently in FP16. When the top two scores are within rounding of each other, Onyx replays the history one token at a time from a clean checkpoint, using CUDA graphs in 8-token blocks.
  • Grammar masks live on the GPU. A Rust engine (regex DFAs and a stack-based JSON Schema parser, exposed through PyO3) works out which tokens are legal in each state. Caching those scans by grammar state lifted long constrained outputs from 0.49–0.99× to as high as 2.0×.
  • Speculation costs almost nothing up front. The draft prefills the prompt only after the target has picked the first token, which cut speculation's added time to first token from 637 ms to 0.3 ms.

A series that follows one prompt, The cat sat on the, through every stage of a transformer. No metaphors: the arithmetic is worked by hand on a model small enough to follow, with a runnable NumPy snippet at each step.

  1. What Actually Happens When You Send a Prompt to an LLM?The whole path from a typed prompt to the first generated token.
  2. Your LLM Doesn’t Read WordsWhy tokenization trips models up on counting the r’s in “strawberry.”
  3. How an LLM Knows “King” Is Closer to “Queen” Than to “Fridge”How an embedding lookup turns token IDs into vectors.
  4. How a Transformer Tells “Dog Chased Cat” From “Cat Chased Dog”Giving each token its position in the sequence.
  5. What Is Attention Actually Calculating?Five tokens through dot products and causal masking, by hand.
  6. Where Do Queries, Keys, and Values Come From?The learned projections that feed attention.
  7. Why One Attention Head Isn’t EnoughTwo heads on the same tokens, then concatenation and projection.
  8. Attention Is Only Half of a Transformer BlockResiduals, layer normalization, and the feed-forward network.
  9. How an LLM Scores Every Token It Could Say NextFrom the final state to logits and softmax probabilities.
