Onyx

An LLM inference engine that holds output to a regex or a JSON Schema as it generates, and makes it faster with grammar-aware speculative decoding.

Greedy output matches the target model running alone, token for token, including the finish reason. Onyx serves an OpenAI-style chat-completions API with streaming, on NVIDIA GPUs through PyTorch and CUDA, and on Apple Silicon through a separate MLX implementation.

Python, Rust, PyTorch, CUDA, MLXRepository on GitHubRace videos

Draft, then verify

A large model writes one token per forward pass. Speculative decoding lets a small draft model guess the next few tokens; the large target model then checks every guess in a single pass, keeps the ones it agrees with, and adds a token of its own. Because the target still decides every token, the output can’t change. Only the number of passes does.

Results

On a Linux RTX 2080 Ti, across a fixed 48-case benchmark, Onyx generated 1.49× faster in aggregate than Qwen3-8B alone, and every output matched the target alone token for token, including the finish reason.

Where it is still slower

Nine of the 48 cases are slower than the target alone: six with very short outputs, at most 21 ms slower, and three longer requests that needed numerical recovery. They count in the aggregate.

How the benchmark is kept honest

The corpus is frozen: 48 cases across 8 workload categories, with a 16-case held-out split. The harness checks every timed run against the target-only output and aborts on any token or finish-reason mismatch, or an incomplete output. Speed is only reported for correct output.

On Apple Silicon

The separate MLX implementation, with 4-bit Qwen models, reached 1.45× with an 8B target. With a 1.5B target it was slower than running alone, at 0.94×. On a [0-9]{4} grammar, draft acceptance rose from 75% with an unconstrained draft to 100% with a grammar-aware one.

Sources: Onyx CUDA README and its performance notes; Mac benchmarks.

How it works

Draft, then verify

Each round, the Qwen2.5-0.5B draft proposes up to three tokens. The Qwen3-8B target scores the current token and every proposal in one forward pass, keeps the longest prefix it agrees with, and adds its own next token, so a round emits one to four tokens. Both KV caches are then cropped back to the accepted tokens.

The target decides every token

That is why greedy output matches the target running alone, and real-model tests check it. Requests with a positive temperature sample from the target alone.

Grammar masks live on the GPU

A Rust engine, with regex DFAs and a stack-based JSON Schema parser exposed to Python through PyO3, works out which tokens are legal in each grammar state from the tokenizer’s raw bytes. Its scans are cached by grammar state and reused as GPU masks, and both models only pick legal tokens. Caching the vocabulary scans lifted long constrained outputs from 0.49–0.99× to as high as 2.0×.

FP16 near-ties are repaired

Scoring several positions in one batch can round differently from one-token decoding. When the two best legal scores at a position are within FP16 rounding of each other, Onyx recomputes them with one-token steps from a clean checkpoint cache. On the validated GPU, CUDA graphs replay the emitted history of unconstrained requests in blocks of up to eight tokens, matching one-token steps bitwise.

The draft runs as CUDA graphs

The draft’s decoder step is reimplemented over its own weights with a static KV cache and captured as CUDA graphs, cutting draft time from about 7.5–9.8 ms to 4.1–4.4 ms per token. Together with CUDA-graph decoding and recovery, this took the aggregate speedup from 1.17× to 1.49×. The draft also waits to read the prompt until the target has picked the first token, which cut speculation’s added time to first token from 637 ms to 0.3 ms.

Built with a coding agent

Onyx was developed with Claude Code as a coding agent. I wrote the agent instructions and handoff documents (a code map, invariants, validation steps), delegated scoped tasks to subagents, and verified their changes with unit tests and real-model GPU tests.
